# Accessibility labels for the book/chapter picker (roadmap item 23)

Goal: the title trigger, the book rows, the chapter cells and the back arrow all
say what they are and, where it applies, whether they are the current choice.

## Task 1: What the picker actually announced

**Files:** `app/read.tsx`

| Control | Before |
| --- | --- |
| Header trigger | "Psalms 23, button" — the passage, not that tapping changes it |
| Book row | no role, no label, no state |
| Chapter cell | "3" |
| Sheet back arrow | "Go back" — which suggests it closes the sheet |

- [x] The trigger's label now leads with the passage and then says what the
      control does: `Psalms 23, choose book and chapter`.
- [x] Book rows get a button role, the book name as their label, and
      `accessibilityState={{ selected }}`. The open book was marked only by font
      weight and gold — nothing a screen reader can see.
- [x] Chapter cells name the book: a bare "3" is meaningless out of the grid,
      and the book name is on screen but not in the cell.
- [x] The back arrow returns to the book list one level up, so it says so
      (`a11y.backToBooks`) rather than borrowing the generic back label.
- [x] Three new keys in all six languages.

## Task 2: The sheet itself

- [x] The title is a `header`, so TalkBack's heading navigation lands on it.
- [x] `accessibilityViewIsModal` on the sheet's root — without it the reader
      behind the dim layer is still reachable by swiping.
- [x] The dim area is hidden from accessibility. It dismisses on tap, but it has
      nothing to announce and gesture-back already closes the sheet. Giving it a
      button role would also put a full-screen target flush against the sheet's
      controls, which the 8dp gap measurement would rightly reject.

## Task 3: Guard it

**Files:** `src/a11y/labels.test.ts`

Two rules general enough to catch the next case, and one that names this one:

- [x] An icon-only Pressable — one whose markup has an `Ionicons` and no `Text` —
      must carry a label. There is no text to fall back on.
- [x] A Pressable that paints itself by an `active`/`selected`/`done` flag must
      carry `accessibilityState`. Colour and weight are not a channel a screen
      reader has.
- [x] The picker's four controls checked by name, because the generic rules
      cannot see them: the book row's selected flag is an index comparison, and
      both rows carry text.

- [x] **A wrapper is not responsible for what it wraps.** The first run blamed
      the OptionSheet and VerseActionSheet backdrops, which contain every control
      in their sheet. The scanner now cuts nested Pressables out of an element's
      own markup.
- [x] **Proved it fails:** removed the chapter cell's state (2 tests caught it),
      the back arrow's label (2 caught it), and the VerseActionSheet action's
      state (1 caught it).

## Task 4: What the general rule found on its own

- [x] `VerseActionSheet`'s bookmark action paints itself with a gold background
      when the verse is bookmarked, and said nothing. Its label already changes
      ("Bookmarked" / "Bookmark"), so it was not silent — but the state belongs in
      `accessibilityState`, which is where the rest of the app puts it.

## Task 5: Measure what is now measurable

- [x] The picker only became visible to `scripts/measure-tap-targets.mjs` once
      its rows had a button role, so the two picker views were added: coverage is
      now **13 views** (was 11, one of item 22's open ends).
- [x] It found something immediately: the **first book row rendered 47dp**. Every
      other row gets a pixel back from its divider border; the first row has no
      divider. `minHeight: TAP_MIN`.

## Task 6: Verify

- [x] `npm test` (108/108), `npm run typecheck`, `npm run lint`,
      `npm run release-check`, `npm run tap-targets` (13 views, 0 problems),
      Android Expo export.
- [x] Labels read back from the rendered DOM in Turkish, German and French —
      "Psalmen 23, Buch und Kapitel wählen", "Psaumes 23, choisir le livre et le
      chapitre", heading role and `aria-modal="true"` all present.

## A limit worth stating

`accessibilityState` is a **native-only** channel in this stack. React Native Web
maps the top-level `aria-selected` prop but does not translate
`accessibilityState.selected` into anything, so the selected state cannot be
observed in the browser harness. (The five `aria-selected` elements a first pass
found on `/pray` were expo-router's tab bar, which passes the ARIA prop directly —
not our chips.)

So for item 23 the browser confirms role, label, heading and modal containment;
the selected state rests on the source guard and on being the same API the other
five selectable surfaces in the app already use. TalkBack on a device is in the
go-live checklist.

## Left open

- Item 28 wants focus moved into the sheet on open and returned on close;
  `accessibilityViewIsModal` here is containment only, not focus management.
- The other five sheets (`OptionSheet`, `ReadingSettingsSheet`, `VerseActionSheet`,
  `DataActionSheet`, `ReminderTimeSheet`) have no `accessibilityViewIsModal` and no
  header role. Item 28 is the natural place to do them together.
- Verse rows still have no button role (item 25).
